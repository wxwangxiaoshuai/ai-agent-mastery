## 数据驱动增长：留存、转化与漏斗

前两节讲的是把人弄进来。这一节讲一个更根本的问题：**人进来之后有没有留下**。

顺序不能反。在留存没跑通之前做增长，等于往一个漏水的桶里灌水 —— 灌得越快，漏得越多，而你还要为每一滴水付钱。

### 留存是唯一骗不了人的指标

其他指标都能自我安慰：注册数低是因为还没推广，转化率低是因为定价没调好，流量少是因为内容还没起来。

只有留存不行。**如果用户用了一次就不再回来，说明你没有解决他的问题，或者解决得不够好到值得他改变习惯。** 这个结论没有别的解释。

所以数据体系的第一优先级是把留存算清楚，而不是先搭一堆漂亮的仪表盘。

先看这几个概念怎么串起来的 —— 下面这个模型可以调参数：改漏斗各层的转化率、月留存率和客单价，看最终的付费用户数和月收入怎么变：

::interactive{type="growthFunnel"}

多试几组你会发现一件事：**把月留存从 70% 提到 80%，效果通常超过把流量翻倍**。

原因是留存进入的是复利公式。流量翻倍是把新增乘以 2，一次性的；留存提高改变的是稳态用户数 `新增 / 流失率` —— 流失率从 30% 降到 20%，稳态用户数直接涨 50%，而且这个效果每个月都在。

这就是为什么「先修留存再做增长」不是一句正确的废话，是一个能算出来的结论。

### 三类问题，三种解法

漏斗上不同位置的问题，解法完全不同。混在一起处理是常见的浪费。

**激活问题（注册了但没有完成核心动作）。**

这是新产品最常见也最容易修的问题。用户注册后不知道该干什么、第一步太麻烦、需要准备的东西他手边没有。

判断信号：注册转激活的比例低于 40%。

解法方向：缩短到达「第一次成功」的路径。给示例数据让他能空手试一次、把注册往后推（先让他用一次再要邮箱）、把首屏从「功能介绍」改成「直接开始」。

**留存问题（激活了但不再回来）。**

判断信号：次周回访低于 20%，或者第 4 周留存低于 10%。

这个最难修，因为它通常意味着产品的价值不够。可能的原因：这是个低频需求（他一个月才用一次，那次周回访本来就不该高）、有更方便的替代方案、或者你解决的问题不够痛。

修之前先分清是哪一种。**低频需求的产品不该用周留存衡量**，用月留存或者「每次需求发生时是否想到你」来衡量。

**转化问题（一直在用但不付钱）。**

判断信号：活跃用户里付费比例低于 2%（免费增值模型下）。

常见原因：免费额度太慷慨（他不需要付费就够用了）、付费墙的位置不对（挡在了他不在意的功能前面）、价值表述不清（他不知道付费能得到什么）。

一个很实用的诊断：**看那些用满了免费额度的用户有多少比例付费了**。如果这个比例也很低，问题在价值不在额度；如果这个比例还行但撞额度的人很少，问题在额度给太多了。

### 最小可用的埋点

不需要接一套复杂的分析平台。一张表 + 几条 SQL 就能回答上面所有问题。

```sql
CREATE TABLE events (
  id         bigserial PRIMARY KEY,
  user_id    text,                    -- 未登录时用匿名 ID
  name       text NOT NULL,           -- 事件名
  props      jsonb DEFAULT '{}',      -- 附加属性（来源、耗时、结果等）
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON events (name, created_at);
CREATE INDEX ON events (user_id, created_at);
```

事件不要贪多。**先埋漏斗上的四五个关键节点就够**：

```python
EVENTS = [
    'page_view',        # 访问（带 from 参数，对应 L19-02 的来源标记）
    'signup',           # 注册
    'first_run',        # 第一次完成核心动作 ← 激活的定义
    'repeat_run',       # 第二次及以后
    'hit_quota',        # 撞到额度上限
    'view_pricing',     # 看了定价页
    'subscribe',        # 付费
]

async def track(user_id: str | None, name: str, **props):
    assert name in EVENTS, f'未登记的事件名: {name}'
    await db.execute(
        'INSERT INTO events (user_id, name, props) VALUES ($1,$2,$3)',
        user_id, name, json.dumps(props),
    )
```

那个 `assert` 很有用。埋点最常见的腐化方式是事件名越来越乱（`first_run`、`firstRun`、`first-run` 同时存在），几个月后数据就没法用了。用一个白名单挡住。

**`first_run` 的定义要仔细想。** 它必须是「用户第一次从你的产品得到价值」的那一刻，不是「点了开始按钮」。定错了，你的激活率会好看但没有意义。

### 队列分析：判断产品是不是真的在变好

看总量会骗人。你的总用户数在涨，可能只是因为你在持续推广，而每一批新用户的留存都在变差。

队列分析（cohort）把用户按注册月份分组，分别看每组的留存曲线：

```sql
WITH cohort AS (
  SELECT user_id, date_trunc('month', min(created_at)) AS c_month
  FROM events WHERE name = 'signup' GROUP BY user_id
),
activity AS (
  SELECT DISTINCT user_id, date_trunc('month', created_at) AS a_month
  FROM events WHERE name IN ('first_run', 'repeat_run')
)
SELECT
  c.c_month,
  (EXTRACT(YEAR FROM a.a_month) - EXTRACT(YEAR FROM c.c_month)) * 12
    + (EXTRACT(MONTH FROM a.a_month) - EXTRACT(MONTH FROM c.c_month)) AS month_n,
  count(DISTINCT c.user_id) AS users
FROM cohort c JOIN activity a USING (user_id)
GROUP BY 1, 2 ORDER BY 1, 2;
```

结果排成一张表：

```
注册月    第0月   第1月   第2月   第3月
2026-01   100     32      21      18
2026-02   140     41      29      —
2026-03   180     67      —       —
2026-04   210     —       —       —
```

看第 1 月这一列：32%、29%、37%。三月的那批明显好于前两批 —— 如果你在二月底做了某个改动，这就是它起作用的证据。

**这是判断「产品是不是真的在变好」的唯一可靠方法。** 总活跃数受推广节奏影响，队列曲线不受。

一个提醒：**队列分析需要时间才有意义**。前两个月的表基本是空的，别因为看不出结论就放弃埋点 —— 数据是攒出来的，你现在不埋，三个月后依然没有。

### 别掉进的几个坑

**一、埋点太多。** 埋了五十个事件，最后一个都不看。先埋七个，用起来了再加。

**二、只看漏斗不看原因。** 知道「注册到激活掉了 70%」没用，你需要知道他们卡在哪一步。补充记录中间步骤，或者更直接 —— 去问几个流失的用户（L19-04 讲怎么建这个渠道）。

**三、拿小样本做决定。** 20 个用户的数据里，转化率从 10% 变成 15% 完全可能是随机波动。样本量小的时候，**用户访谈的信息量远大于统计数字**。一个用户告诉你「我以为要付费才能试」，比任何漏斗图都有用。

**四、优化了指标但没优化产品。** 把注册流程做得更"顺滑"（比如默认勾选、隐藏取消入口）能拉高注册率，但这些人不会留存，你只是把问题往后推了一格。

**五、没有对照就归因。** 「我改了首页，第二周注册涨了 30%」—— 也可能是那周有人转发了你的产品。一人公司很难做严格的 A/B 测试（样本不够），务实的做法是**承认归因的不确定性**，把改动和外部事件都记在一个时间线上，看长期趋势而不是单周波动。

### 动手 5 分钟

搭起最小的漏斗，重点是定义清楚「激活」。

1. 写下你的 `first_run` 定义：用户做到哪一步，才算「从产品得到了价值」？（注意不是点了开始按钮）
2. 建 events 表，埋上七个关键事件，带上白名单 assert。
3. 用上面的模型试参数：找出「留存提 10 个百分点」和「流量翻倍」哪个对你的稳态用户数影响更大。

**验收标准**：你能说出自己的注册率、激活率、次周回访率三个数字（哪怕样本很小），以及三者里最该先修的是哪一个。如果激活率低于 40%，先修激活 —— 那是最容易修也最有效的一环，在它修好之前做推广是浪费。

### 要点总结

- **留存是唯一骗不了人的指标**；在留存跑通前做增长，等于往漏水的桶里付费灌水。
- **留存进入的是复利公式**：稳态用户数 = 新增 / 流失率。留存提 10pp 的效果常常超过流量翻倍。
- 三类问题三种解法：**激活**（<40% 先修这个，最容易见效）、**留存**（最难，先分清是不是低频需求）、**转化**（看撞额度的人付费率来区分是价值问题还是额度问题）。
- 埋点**先埋七个关键事件**就够，用**事件名白名单 assert** 挡住命名腐化。
- **`first_run` 要定义成「第一次得到价值」**，不是「点了开始按钮」，否则激活率好看但无意义。
- **队列分析是判断产品是否真的在变好的唯一可靠方法**；总活跃数受推广节奏影响，队列曲线不受。
- 样本小的时候，**一次用户访谈的信息量远大于统计数字**；20 个人的转化率波动说明不了任何事。
- 每周报表里**「本周改动」那一栏最关键** —— 没有它，你永远不知道指标变化是什么引起的。
