## 摘要

这是一份**内容架构非常出色、但代码可执行性系统性失守**的课程。

结构、选题、编排、取舍判断、写作质量都在同类中文技术课程里属于上游——尤其 M17–M19 的独立开发主线和 `scripts/check-curriculum.mjs` 这套自动化守护体系，是很少有课程项目会做的事。

但精读 119 节课之后，一个结论压过其他所有发现：

> **课程里的 Python 示例代码，绝大多数从未被执行过。**

这不是"有几个 typo"。是 `SyntaxError`、`NameError`、`TypeError`、方法写在 class 外面、调用不存在的 API 参数、`while not done` 里 `done` 从未定义、旗舰项目的核心函数对两家 API 都非法。而且这些错误**高度集中在每节课最核心的那段代码上**——讲"崩了也能续上"的检查点代码第一次工具调用必崩，讲"优雅降级"的降级链主档永远失败，讲"用数据说话"的对比实验混杂了变量。

同时存在一个更隐蔽的问题：**全站 148 处 OpenAI 模型标识（`gpt-4o` / `gpt-4o-mini`）指向已下线的模型**，而守护它的 C5/C14 检查项因为白名单本身没更新而全程绿灯。

好消息是：这两类问题都是**机械可修的**，不需要重写内容。修完之后这是一门很好的课。

## 一、系统性问题（优先级最高）

修单点不如修模式。以下六条各自覆盖十几到上百处。

### S1 · 代码从未被执行 —— 60+ 处高危缺陷

按类型归纳（每类给 2–3 个代表，完整清单见第二节）：

| 缺陷类型 | 典型位置 | 后果 |
|---------|---------|------|
| **语法错误** | `project-p6.md:529-530` 半角双引号嵌套在双引号字符串内 | `compare.py`（P6 号称"最有价值的产出"）根本不能解析 |
| **未定义符号** | `lesson-l16-01.md` `while not done:`（`done` 从未定义）；`lesson-l10-03.md` `return END`（`END` 未 import） | 第一行即 `NameError` |
| **方法写在 class 外** | `lesson-l08-05.md` 全节 6 个方法用 `def xxx(self, ...)` 写在模块顶层 | 整节代码没有一个能跑 |
| **调用不存在的方法/参数** | `project-p8.md` `Collection.update(where=...)`（Chroma 无此参数）；`lesson-l09-02.md` `container.exec_run(timeout=)` | `TypeError` / 参数被静默忽略 |
| **SDK 对象与 dict 混用** | `lesson-l07-03.md` 把 `ChatCompletionMessage` 丢进 `json.dumps`；`lesson-l11-02.md` 把 `AIMessage` 丢进 OpenAI SDK | 两个方向的同型错误 |
| **跨厂商 API 结构非法** | `project-p3.md` `assemble()` 产出 `{"role":"system", "content":[{"cache_control":...}]}` | Anthropic 不接受 `role:system`（L01-03 自己刚强调过），OpenAI 不认 `cache_control` |
| **字面 `...` 占位符** | M6-17 / M11-13(×2) / M13-17 / M14-17 / `project-p16.md` Step 4 / `lesson-l18-*` | 共 8 处，其中一处落在毕业设计"RAG + 记忆串联"的核心代码上 |
| **并发安全双标** | `lesson-l07-04.md` `CircuitBreaker` 是无锁 dataclass，同节后半段却给 `TokenBucket` 加了 `threading.Lock` | 熔断器读-改-写竞态 |
| **超时保护本身会挂死** | `project-p7.md` `@resilient` 每次重试新建 `ThreadPoolExecutor(max_workers=1)`，`future.cancel()` 对已运行任务无效，`shutdown(wait=True)` 反而阻塞到线程结束 | 线程泄漏 + 超时保护失效 |

**最刺眼的一点**：这些错误几乎全部落在**该节课要教的那个核心机制**上。讲健壮性的 M7 有 4 处必崩，讲记忆的 M8 有 7 处，讲沙箱安全的 M9 有 5 处。学员照着敲到最关键处就断了，而这恰恰是最打击信心的位置。

### S2 · 模型标识全站过期，且守护机制被绕过

全站 `content/` 扫描：

| 标识 | 出现次数 | 状态 |
|------|---------|------|
| `gpt-4o-mini` | 96 | **API 已于 2026-02-16 返回 404** |
| `gpt-4o` | 52 | **同上** |
| `gpt-4o-2024-11-20` / `-08-06` | 2 / 2 | 随 `gpt-4o` 一同下线 |
| `claude-sonnet-4-20250514` | 11 | 旧代但仍有效 |
| `claude-sonnet-5` / `claude-opus-5` / `claude-haiku-4-5` | 10 / 5 / 3 | 当前 |

**148 处 OpenAI 侧示例在 2026-07 已不可运行。**

守护本该拦住这件事，但三层都漏了：

1. **C5 白名单本身就是过期的**——`src/data/models.ts` 把 `gpt-4o` / `gpt-4o-mini` 列为合法，所以 C5 全绿。
2. **C14（校准日期 <180 天）形同虚设**——`CALIBRATED_ON = '2026-07-27'` 是 3 天前，但白名单内容根本没跟着更新。**这是全站唯一一个改一个字符串就能骗过的检查项。**
3. **C5 正则覆盖不全**——`/\b(gpt-[0-9o][\w.-]*|claude-...|gemini-[\w.-]*)\b/g` 不覆盖 `text-embedding-3-small`（16 处）、`llama3.2`、`qwen2.5-*.gguf`，也不覆盖不以 `gpt-` 开头的 OpenAI 推理模型（`o3` / `o4-mini`）。

附带两个数据层缺陷：`embedding` 档的 `models: []` 是空数组（`defaultModelOf('embedding')` 返回 `undefined`，而该档正文写着"建库与查询必须用同一个模型"——唯一强调必须锁定模型的档反而没登记任何 ID）；`nano` 与 `small` 两档的模型列表完全相同，五档分类里有两档在实现上不可区分。

### S3 · 编造的数字被当作事实呈现

分块精度 75/82/88%（L04-02）、召回率/精确率/延迟四行对照表（L04-04）、四轮优化曲线（L04-05）、框架评分矩阵（L14-01）、"选择噪音降了 70%"（L06-08/P6）、"快 3-5 倍"（L19-07）——**无数据集、无来源、无测量条件**。

学生会把这些当成可引用的结论。而 M13 用 8 节课教评估方法论，M19 教"没有对照就归因"是坑——课程自己在正文里反复违反自己教的东西。

两个例外值得表扬：M18 全篇给了三层免责声明；`lesson-l19-03.md` 的示例数据**内部完全自洽**（队列表 32/100、41/140、67/180 对应正文 32%/29%/37%；周报按来源 142+201+77=420、18+9+11=38、12+3+6=21 三行与总数逐一吻合）。这说明作者做得到，只是没有全站坚持。

## 四、结构性观察

**阶段划分整体合理**，7 阶段 19 模块递进清晰，`stages` 数组是全站派生真源且被 C13 守护——这是好设计。问题只在块注释未同步（P1-9）。

**M17–M19 是全课程最好的一段。** 从 AI Coding 到商业化到上线运营，这条线在中文技术课程里极少见，且写得克制、不画饼。M18 全篇给三层免责声明、`l18-04` 的支付状态机 + DB 唯一约束幂等 + `reconcile()`、`l18-06` 的 `delete_user(dry_run=True)`，都是可以直接用的工程实践。

**M19 是全站收尾典范。** `lesson-l19-06.md` 是单节最高分：负责任地处理倦怠与心理健康（给可判别的早期信号，明确"问题通常不在意志力，在工作方式的可持续性"，信号升级时建议找专业人士，并点出"没有同事会注意到你不对劲"这个独立开发者特有的风险），并把"退出"正当化为五种正当结局。`lesson-l19-05.md` 的运营 Agent 边界表（按"错了的代价和谁承担"而非技术难度划线）+ 只读数据库角色 + 日报 prompt 三约束（其中"无异常就说无异常"防模型为显得有用而制造问题），是全课程 HITL 与护栏思想最漂亮的一次自我应用。

**唯一的结构性硬伤是 P0-27**：课程的真正末课是一节 prompt 模板课，而写好的结语被放在了倒数第二节。调整顺序即可，成本极低、收益很高。

**项目与课程的贴合度整体不错**，`project-p18.md` 是全站最好的项目（三层免责声明、13 个 checkbox、5.5 小时分期、`api_calls` DDL 里 `success boolean NOT NULL -- 失败也要记，成本已经产生` 这种细节），`project-p19.md` 是最诚实的（"唯一一个成败不由你单独决定的项目"，工期跨 4 周与"需要真实时间流逝才有数据"一致）。

**`systematic-debugging` skill 被误用了两次**（P18 用它做合规检查清单、l19-07 类似）——这是把 Superpowers 的 skill 当通用名词用了，属系统性小问题。

## 六、工程质量（站点本身）

### 亮点

**`scripts/check-curriculum.mjs` 是这个项目最大的资产。** C1–C21 共 21 条检查（C16–C21 是本轮新增的静态图几何校验），零依赖、error/warn 分级、`--strict` 可升级、被 `pnpm build` 和 CI 前置。**把历次 review 的结论固化成机器检查**，是很少有课程项目会做的工程决策。

**上一轮 diagrams review 的头号问题已修复**：`src/components/diagrams/_shared/layout.ts:76` 的 `layoutEdges()` 用 `inferSides(dx, dy)` 几何推断端口并自动在 `step`/`bezier` 间选择，解决了 101/231 条边退化成 top→top 的问题。C20 把"未显式指定端口"降为 warn 与这个运行时兜底是配套的，设计合理。

**`.github/workflows/deploy-pages.yml` 质量很高**：`checkout@v4` + `pnpm/action-setup@v4` + `node-version: 24` + `cache: pnpm` + `--frozen-lockfile`，`pnpm check` 单独成步（带中文注释说明原因），`concurrency: {group: pages, cancel-in-progress: true}`，Pages 未启用时给出可操作报错。

## 七、改进计划

分四期。每期都以"跑得通"为验收，不追求一次做完。

### 第一期：止血（1–2 周，最高优先级）

目标：**让全新 clone 能构建、让第一个项目能跑通、让末课不再自相矛盾。**

1. **修 P0-30**（lockfile）——半小时，但它决定 CI 能不能用。先做这个。
2. **修 P0-27 / P0-28**（M19 末课顺序 + "108 节"）——改课程顺序 + 一个数字，收益极高。
3. **模型标识换代**（P0-29）：
   - 先更新 `src/data/models.ts` 白名单（含 embedding 档补齐、nano/small 区分开）
   - 再全站 `gpt-4o-mini` → 新 nano/small 档、`gpt-4o` → 新 mid 档
   - 148 处可脚本化替换，人工复核上下文语义
4. **修 M1 的双语言残留**（`project-p1.md` Step 1）——学员的第一个项目不该违反主线定位。
5. **修 P0-1**（P6 语法错误）——一行改动，解锁整个 `compare.py`。

### 第二期：代码可执行性（4–6 周，工作量最大）

目标：**每一段 Python 都真的跑过一次。**

建议做法不是"逐条改 P0 清单"，而是**建立一条可复用的验证管道**：

1. 写一个抽取脚本，把所有 `.md` 里的 ```python 代码块抽成独立文件（约 440 个）。
2. 先做**静态门禁**：`python -m py_compile`（抓 P0-1 这类语法错误）+ `ruff check --select F`（抓 `F821` 未定义名、`F401` 未使用导入——这一条就能自动抓出 P0-15、P0-21、P0-23 和全部字面 `...` 占位）。
3. 对可独立运行的片段（不需要真实 API key 的），补 mock 后做 `pytest` 冒烟。
4. 把第 2 步固化成 **C22 检查项**，进 `pnpm check`。

这一步做完，S1 的 60+ 处缺陷会有一大半被自动定位，而且**再也不会回归**——这比手工修一遍有价值得多。

按模块的修复优先级（缺陷密度 × 位置重要性）：**M8 > M7 > M10 > M9 > M11 > M6 > M3 > M16 > M17**。

### 第三期：可信度与一致性（3–4 周）

1. **清理编造数字**（S3）：每一处基准数字，要么补上"来源/测量条件"，要么改成"量级示意，非实测"的免责标注。参照 M18 的三层免责声明写法。

4. **跨模块引用校验**：新增 **C23**——扫描正文里的 `M\d+` / `L\d\d-\d\d` / `P\d+` 引用，校验目标存在且模块主题匹配（能抓出 L18-05 的"M12 讲过路由"和 P18 的 L17-13 错位）。

## 八、总评

这份课程的**内容判断力明显高于它的执行精度**。

作者知道该讲什么、该按什么顺序讲、哪些是反模式、哪些数字不该信、什么时候该给学员划边界——这些是最难教也最难补的东西，而这门课都有。`scripts/check-curriculum.mjs` 更说明作者理解"把结论固化成机器检查"的价值。

失守的地方集中在**"写完之后有没有跑一遍"**。这不是能力问题，是流程问题——`lesson-l17-13.md` 那一节的准确度证明作者完全做得到，只是没有一条机制强制每段代码都过这一关。

所以第二期（建立代码执行门禁）是整个改进计划里回报最高的一项。做完之后，这门课的评分会从"内容 A- / 代码 D"变成整体 A-，而这只需要一个抽取脚本加两条 lint 规则。
